# 🎵 SyncBeat — اتاق موسیقی مشترک

یه سایت ساده که باهاش می‌تونی با دوستت هماهنگ به موسیقی گوش بدی:

- **ورود مهمان**: بدون رمز و ایمیل، فقط یه اسم (۲ تا ۲۰ حرف) — اسم و آی‌دی مهمانِ مرورگر نگه‌داشته می‌شه.
- یه نفر **اتاق می‌سازه** و یه **کد ۵ حرفی** می‌گیره؛ نفر بعدی با کد یا **لینک دعوت (QR)** وارد می‌شه.
- آهنگ رو می‌تونی هم با **لینک** بدهی (MP3 مستقیم / یوتیوب / ساندکلاد) و هم با **آپلودِ فایل از کامپیوتر** — دکمه‌ی 📁 کنار ورودی لینک.
- **صف پخش + تاریخچه**، **چت**، **ری‌اکشن**، و **دعوت دوستان**. آهنگ اول خودش شروع می‌شه و **صف بدون کلیکِ دوباره ادامه پیدا می‌کنه**.
- **کنترلِ گروهیِ صف**: هرکسی آهنگِ خودش رو **جابه‌جا** می‌کنه («⏭ بعدی» / «↑»)، همه می‌تونن **رأی** بدن (♡/♥) و هاست می‌تونه ترتیب رو بین «اضافه‌شده» و «رأی» عوض کنه.
- **جستجوی یوتیوب** داخل خودِ سایت — اگه `YOUTUBE_API_KEY` تنظیم شده باشه.
- **نقش‌ها**: هاست (👑) کیک/انتقال هاست/پاک کردن صف داره؛ «شنونده» (🎧) فقط گوش می‌ده؛ حالت **فقط DJ** (`djOnly`) کنترل رو به هاست محدود می‌کنه.
- **پلی/پاز/جابه‌جایی/ولوم/سرعت پخش** برای همه هماهنگ می‌شه و با ضربان قلب سرور از آفلاین شدن drift جلوگیری می‌شه — **در هر دو جهت**: اگه سرور بگه «پاز» ولی یکی داره پخش می‌کنه، اصلاح می‌شه.
- وضعیت اتاق‌ها در یک دیتابیس SQLite داخلیِ خودِ Node (`data/syncbeat.db`) ذخیره می‌شه — تغییرِ یه اتاق فقط همون اتاق رو می‌نویسه، نه همه رو. اگه از نسخه‌ی قبلی `data/rooms.json` داشته باشی، **خودکار import می‌شه** (و `rooms.json.imported` کنارش می‌مونه). اتاق خالی بعد از ۲۴ ساعت پاک می‌شه. تعداد کل اتاق‌ها با `MAX_ROOMS` (پیش‌فرض ۲۰۰۰) محدوده.

## امنیت و هویت

- **بدون پسورد**: فقط اسم مهمان. هویت هر اتصال یه `uid` تصادفی‌ایه که سرور صادر می‌کنه — گفته‌ی کلاینت (`guestId`) هیچ‌وقت هویت نیست و فقط برای اسم و بن به‌کار می‌ره، پس جعل‌پذیر نیست.
- **هاست = توکن مخفی**: موقع ساخت اتاق یه توکن تصادفی فقط به سازنده داده می‌شه (localStorage مرورگرش) و هرگز broadcast نمی‌شه. کسی بدون توکن نمی‌تونه هاست بشه؛ حتی اگه کد اتاق را حدس بزنه.
- **رفرش = حفظ هاست**: اگه هاست وصلش قطع بشه، ۳۰ ثانیه فرصت داره با توکنش برگرده؛ وگرنه توکن جدیدی به یکی از اعضا داده می‌شه و توکن قبلی می‌میره. اگه اون ۳۰ ثانیه توی اتاقِ خالی تموم بشه، هرکسی بعداً وارد بشه دوباره ۳۰ ثانیه صبر می‌کنه تا هاست مشخص بشه — یعنی اتاق هیچ‌وقت بی‌هاست نمی‌مونه، و صاحب توکن تا آخرِ اون پنجره می‌تونه توکنش رو پس بگیره.
- **مالکیتِ صف = توکن مخفیِ دوم**: هر عضو موقع ورود یه `ownerSecret` می‌گیره (localStorage، کنار توکن هاست). سرور فقط **هش** اونو توی `addedBy` می‌ذاره و با صف broadcast می‌کنه، پس همه می‌بینن چه کسی آهنگ رو اضافه کرده ولی فقط صاحبش (یا هاست) می‌تونه حذفش کنه. اینجا هم `guestId` به‌درد نمی‌خوره — کلاینت هر رقمی بفرسته قبوله.
- **کیک = بن (بهترین تلاش)**: آیدی مهمانِ کیک‌شده در لیست بن اتاق می‌مونه؛ پاک کردن localStorage ازش رد می‌شه ولی کیک فوری مجدد رو می‌گیره.
- **origin محدوده**: فقط origin خود سرور (و `EXTRA_ORIGINS` با کاما جدا) می‌تونه وصل بشه — چون WebSocket قانون CORS نداره.
- **rate-limit**: هر IP در دقیقه حداکثر ۳۰ تلاش ساخت/ورود اتاق، برای جلوگیری از حدس کد.
- **پشت پراکسی**: اگه سرور پشت یه پراکسی مثل Render یا nginx باشه، بدون تنظیم، همه‌ی کاربرا پشت یک IP دیده می‌شن و سهمیه‌ی rate-limit بین‌شون تقسیم می‌شه. بذار `TRUST_PROXY=1` تا کلاینت از سر `X-Forwarded-For` خونده بشه. **فقط وقتی این کار رو بکن که دقیقاً یک پراکسی جلوی سرورت باشه** — بدون پراکسی، خود کلاینت می‌تونه هدر رو جعل کنه و از محدودیت رد بشه.

## تست

```bash
npm test
```

خودش یه سرور تستی با دیتای موقت بالا می‌اره (پورت‌ها یکتا هستن تا اجرای پشت‌سرهم تداخل نداشته باشه) و **۴۶ بررسی** رو اجرا می‌کنه:

- **`test/smoke-client.js`** — `app.js` رو روی یه DOM ساختگی بالا میاره و توابع اصلی‌اش رو یک‌بار صدا می‌زنه تا مطمئن بشی صفحه اصلاً بالا میاد.
- **`test/e2e.js`** — ۴۴ سناریو: هویت، هاست، بن، سرعت، صف (شاملِ جابه‌جایی، رأی و مرتب‌سازی)، origin، rate-limit، بازیابی هاست، مالکیتِ صف، ادامه‌ی خودکار صف، رد شدن echoهای کهنه، heartbeat سبک، سقف اتاق‌ها، flush هنگام خاموشی، آپلود فایل، اتاق خصوصی، جستجوی یوتیوب و مهاجرت از `rooms.json`.

> این‌ها سناریوهای سرورن — هیچ‌کدام صدا پخش نمی‌کنن. پخشِ واقعیِ صدا در مرورگر باید دستی چک بشه.

نکته: بیشتر موارد بالا قبلاً باگ بودن — هرکدوم قبل از اصلاح روی سرور واقعی بازتولید شدن، بعدش تست بازگشتی خوردن.

## اجرای لوکال

نیاز به Node.js نسخه **۲۲٫۵** به بالا داری (برای `node:sqlite` — ذخیره‌سازی داخلیِ Node، بدون هیچ وابستگیِ نصبی).

```bash
npm install
npm start
```

بعد برو به `http://localhost:3000`. برای تست، یه تب اتاق بساز و توی یه تب دیگه (یا مرورگر دیگه) با کد وارد شو.

## دیپلوی آنلاین

چون هماهنگ‌سازی نیاز به سرور دائمی داره، از سرویس‌هایی مثل **Render** یا **Railway** استفاده کن (نه Netlify/Vercel که فقط استاتیک هستن).

### Render
1. کد رو روی یه ریپوی GitHub بذار.
2. توی Render یه **Web Service** جدید بساز و ریپو رو وصل کن.
3. تنظیمات:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
4. Render خودش پورت رو از طریق متغیر `PORT` می‌ده و سرور اونو می‌خونه.
5. یه متغیر محیطی دیگه هم بذار: **`TRUST_PROXY=1`** — ترافیک از پراکسی Render رد می‌شه، و بدون این تنظیم، همه‌ی کاربرا پشت یک IP حساب می‌شن و سهمیه‌ی ۳۰ تلاش/دقیقه بین‌شون مشترک می‌شه.

### Railway
1. ریپو رو وصل کن یا با `railway up` آپلود کن.
2. Railway به‌صورت خودکار `npm install` و `npm start` رو اجرا می‌کنه.
3. متغیر محیطی **`TRUST_PROXY=1`** رو هم اضافه کن (به همان دلیل بالا).

> هر جای دیگه‌ای که سرور مستقیم جلوی اینترنت باشه (بدون پراکسی)، `TRUST_PROXY` رو **ذخیره نکن**.

## نکته‌ها

- **لینک MP3** باید مستقیم و قابل دسترس باشه (مثلاً روی یه هاست که CORS اجازه بده). خیلی از هاست‌ها پخش مستقیم از دامنه‌ی دیگه رو محدود می‌کنن — اگه لینکت کار نکرد، همون آهنگ رو **آپلود کن**.
- **آپلود فایل**: فایل صوتی مستقیم می‌ره روی سرور (`data/uploads/`) و با همون مکانیزمِ پخشِ معمولی (حتی با Range برای seek کردن) سرو می‌شه. محدودیت‌ها:
  - هر فایل حداکثر **`MAX_UPLOAD_MB`** (پیش‌فرض ۳۰ مگابایت)
  - جمع کل فایل‌ها **`MAX_UPLOAD_TOTAL_MB`** (پیش‌فرض ۵۱۲ مگابایت)
  - هر IP در ساعت حداکثر **۲۰ آپلود**، و فقط از origin خودِ سرور
  - فقط پسوندهای صوتی (`mp3, m4a, aac, ogg, opus, wav, flac, …`) قبول می‌شه
  - فایل‌هایی که دیگه هیچ اتاقی بهشون اشاره نمی‌کنه، بعد از **۲۴ ساعت** پاک می‌شن
  > ⚠️ **دیسک Render (پلن رایگان) موقتیه** — آپلودها با هر ری‌دپلوی پاک می‌شوند. برای ماندگاری، یا پلن پولی با دیسکِ دائمی بگیر یا آپلودها رو به یه object storage وصل کن.
- **جستجوی یوتیوب**: یوتیوب برای جستجو هیچ راهِ رسمیِ بدون کلید نداره، پس این قابلیت به `YOUTUBE_API_KEY` گره خورده (بخشِ متغیرهای محیطی). بدون کلید، جعبه‌ی جستجو می‌گه خاموشه و بقیه‌ی راه‌ها (لینک مستقیم و آپلود) دست‌نخورده کار می‌کنن. جستجو **سمتِ سرور** انجام می‌شه تا کلید هرگز به مرورگر نرسه و مشکلِ CORS هم پیش نیاد. هر جستجو حدود ۱۰۰ واحد از سهمیه‌ی روزانه‌ی ۱۰٬۰۰۰‌تاییِ رایگان Google کم می‌کنه.
- **یوتیوب**: هر لینک استاندارد یوتیوب (watch، youtu.be، shorts، embed) کار می‌کنه. **SoundCloud** هم پشتیبانی می‌شه.
- **سرعت پخش و SoundCloud**: ویجت ساندکلاد اصلاً playback-rate نداره. اگه آهنگِ ساندکلاد لود بشه، سرعت اتاق به‌خودی خود برمی‌گرده روی `1×` و تا آخرِ اون آهنگ تغییر سرعت قبول نمی‌شه — وگرنه ساعت سرور از صدا جلو می‌افتاد و هر ۵ ثانیه مجبور به seek می‌شد.
- **autoplay**: آهنگ اول و هر آهنگِ بعدیِ صف خودش شروع می‌شه. اگه مرورگر به‌خاطر سیاست autoplay جلوی اولین پخش رو گرفت، یه‌بار روی صفحه کلیک کن — heartbeat هر ۵ ثانیه دوباره تلاش می‌کنه.
- اتاق‌ها بعد از ری‌استارت سرور از `data/rooms.json` برمی‌گردن (پخش متوقف می‌شه ولی صف/چت/تاریخچه می‌مونه).

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `PORT` | `3000` | پورت سرور |
| `SB_DATA_DIR` | `./data` | پوشه‌ی `rooms.json` و آپلودها |
| `EXTRA_ORIGINS` | — | originهای اضافه‌ی مجاز (با کاما جدا) |
| `TRUST_PROXY` | `0` | `1` وقتی پشت یک پراکسی هستی — rate-limit از `X-Forwarded-For` می‌خونه |
| `HOST_GRACE_MS` | `30000` | فرصتِ برگشتن هاست بعد از قطع اتصال |
| `MAX_ROOMS` | `2000` | سقف تعداد اتاق‌های همزمان |
| `MAX_UPLOAD_MB` | `30` | حداکثر حجم هر فایل آپلودی |
| `MAX_UPLOAD_TOTAL_MB` | `512` | سقف جمع کل فایل‌های آپلودشده |
| `YOUTUBE_API_KEY` | — | کلید Google برای جستجوی یوتیوب (اختیاری — بدون آن جستجو خاموش است) |

## ساختار فایل‌ها

```
package.json      # وابستگی‌ها و اسکریپت‌ها (npm test)
server.js         # سرور Express + Socket.IO و منطق هماهنگ‌سازی
lib/
  store.js        # ذخیره‌سازی (SQLite از node:sqlite — بدون وابستگیِ نصبی)
test/
  e2e.js          # تست خودکار (سرور تستی خودش را spawn می‌کنه)
  smoke-client.js # بالا اومدن client روی DOM ساختگی — گرفتن خطاهای زمان اجرا
  raise-sig.js    # ویندوز: سیگنال shutdown را خودِ پروسه بالا می‌زند تا flush تست شود
data/             # ذخیره‌ی اتاق‌ها و آپلودها (در .gitignore)
public/
  index.html      # صفحه‌ی اصلی
  style.css       # استایل
  echo.js         # تشخیص اینکه رویدادِ پلیر از کاربره یا از دستورِ سرور
  app.js          # منطق سمت کلاینت (پلیر و سوکت)
```
